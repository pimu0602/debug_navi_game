## 1. コンセプト

**「壊して覚える、安全な工場」**

新人技術者が、実際の制御盤立ち上げを疑似体験できる2D見下ろし型シミュレーションゲーム。
操作は自由。ただし間違った操作にはリアルな結果(警告〜発煙・発火)が返ってくる。
失敗から「なぜ手順書があるのか」を体で理解させることを狙いとする。

## 2. 基本仕様

| 項目 | 内容 |
|---|---|
| タイトル | 仮称「デバッグナビ」(正式タイトルは完成間際に決定) |
| ターゲット | 新人技術者(教育用) |
| 1プレイ時間 | 20〜30分(1ステージあたり) |
| プレイ環境 | PCブラウザ(マウス+キーボード) |
| 視点 | 2D見下ろし型、工場マップを歩き回る |
| ビジュアル | ドット絵(レトロRPG風)、演出はコミカル寄りで統一 |
| 評価 | 合格/不合格のシンプル判定+クリア後に模範手順との比較表示 |
| ステージ解放 | 最初から全ステージ選択可(復習しやすさ優先) |
| リプレイ性 | 仕込み不良を毎回ランダム生成 |
| 記録 | 操作ログ・クリア履歴をブラウザ内(localStorage)に保存 |

## 3. ステージ構成(手順書の工程がそのまま章立て)

| Stage | 工程 | 対応ステップ | 主な学び |
|---|---|---|---|
| 1 | 導通チェック編 | Step 1〜11 | 無電圧確認、テスター(Ωレンジ)、線番照合、短絡発見 |
| 2 | 電源投入編 | Step 12〜16 | 一次電源→主電源→CP個別ON、異音異臭への対応 |
| 3 | PLC接続・初期設定編 | Step 17〜24 | 型式確認、通信設定、I/O割付、書き込みとバックアップ |
| 4 | 機器通信設定編 | Step 25〜29 | 局番/IPアドレス、ランプ確認、診断画面 |
| 5 | I/O入力チェック編 | Step 30〜31 | 図面とPLCモニタの照合、センサー反応確認 |
| 6 | 運転準備編 | Step 32〜40 | 非常停止、アラーム処理、運転準備条件 |
| 7 | I/O出力チェック編 | Step 41〜43 | 強制ON/OFF、強制解除の徹底 |
| 8 | エアー・手動操作編 | Step 44〜47 | エアー投入の安全確認、1軸ずつの動作確認 |
| 9 | ティーチング・原点復帰編 | Step 48〜55 | 位置登録、個別→全原点、インターロック |

※ 開発はStage 1(導通チェック編)から着手し、遊びの手触りを検証してから横展開する。

## 4. ゲームフロー(1ステージ)

```
ステージ選択
  ↓
ブリーフィング(今日のミッション説明。手順書は"渡されない")
  ↓
工場マップで自由行動
  ├ 機器に近づいて調べる/操作する
  ├ 図面を開く(いつでも)
  ├ ベテランNPCに話しかける(AIチャット)
  └ テスターで測定する
  ↓
ステージ目標達成(例:導通チェック完了+CP全OFF)
  ↓
合格/不合格判定 → 模範手順との比較画面
  ↓
(不合格・大ミス時は直前のチェックポイントから再開)
```

## 5. マップ上の配置物(Stage 1の例)

| 配置物 | 近づいて操作すると出る選択肢の例 |
|---|---|
| 制御盤(正面) | ブレーカーを見る/CPを操作する/端子台を調べる/扉を閉める |
| 主電源ブレーカー | ONにする/OFFにする/レバー位置を確認する |
| CP群 | 個別にON/OFF(どれをONにしたか記録される) |
| 端子台 | テスターを当てる(2点選択) |
| 工具置き場 | テスターを取る/ペンを取る |
| ベテランNPC | 話しかける(AIチャット起動) |
| 壁の元電源 | ONにする/OFFにする(Stage 2以降) |
| ロボットコントローラ | IPアドレスを設定する/パラメータを見る/電源を見る(Stage 3以降) |

**重要な設計方針:選択肢には「今やると危険な操作」も常に混ぜる。**
例:無電圧確認前でも「主電源をONにする」は選べる → 選ぶと事故につながる。

## 5.5 Stage 1 マップレイアウト案(叩き台)

```
┌──────────────────────────────────────────────┐
│ [壁の元電源]        [制御盤]███████           │
│                     主電源ブレーカー│CP群│端子台 │
│                                              │
│                          (盤の前=作業エリア)   │
│ [工具置き場]                                  │
│  テスター/ペン           [作業机]              │
│                          図面が置いてある      │
│                                              │
│ [ベテランNPC]                                 │
│  休憩スペース                                 │
│                        [入口]★スタート地点    │
└──────────────────────────────────────────────┘
```

配置の意図:

- **入口(スタート)は右下**、制御盤は上壁。部屋を横切る間に工具置き場と作業机が目に入る動線
- **工具置き場は入口から制御盤への途中**に置き、「まずテスターを取る」流れが自然に生まれるように
- **ベテランNPCは左下の休憩スペース**。制御盤から一番遠い位置にして「わざわざ歩いて聞きに行く」距離感を再現
- **作業机に図面**を置く(画面上部の常設ボタンとは別に、マップ上でも図面の存在を見せる)
- 壁の元電源はStage 1では操作不要だが、マップには最初から置いておく(Stage 2以降で同じマップを使い回す)

※ この配置はフェーズ1-2(マップ画面の実装)で実際に表示しながら調整する。

## 6. テスターシステム

- ファンクション切替:**電圧(V)/電流(A)/抵抗(Ω)** の3種
- 測定は「当てる2点を自分で選ぶ」方式(端子台の線番リストから選択)
- 間違ったレンジで測ると:
  - Ωレンジで通電中の回路 → テスター破損(中ミス)
  - VレンジのAC/DC間違い → 異常な値が表示され、判断を誤る
- 正しい測定をすると図面の該当箇所に自動でマーカーが付く(「ペンでなぞる」の再現)

## 7. ミス3段階システム

| レベル | 例 | 結果 |
|---|---|---|
| 軽ミス | CPの戻し忘れ/図面未確認で操作/記録漏れ | 後の工程で警告イベント発生、減点 |
| 中ミス | 無電圧確認せず導通チェック/レンジ間違い | テスター破損・測定やり直し、時間ロス |
| 大ミス | 短絡を見逃して主電源ON/強制ON残しでエアー投入 | 発煙・発火演出 → 直前のチェックポイントから再開 |

チェックポイントは「手順書の工程の区切り」に自動設定(例:無電圧確認完了時点、CP全OFF完了時点)。

**演出テイスト:コミカル寄りで統一。**
発煙・発火もドット絵らしいデフォルメ表現(モクモクした煙、コゲたキャラの顔など)にして、新人が萎縮せず何度も失敗できる空気をつくる。ただし失敗の直後に「実機ならどうなっていたか」を一言添えて、現実の重大さは言葉で伝える。

## 8. ベテランNPC(AIチャット)

- 工場マップ内にNPCとして配置。**歩いて話しかけに行く**(気軽に聞けない距離感を再現)
- 話しかけるとチャットウィンドウが開き、**Claude APIによる自然な会話**で応答
- AIには「現在のステージ/プレイヤーの操作履歴/仕込まれた不良の情報」をコンテキストとして渡す
- 応答方針(AIへの指示):
  1. 答えを即答しない。まず考え方・着眼点を教える
  2. 同じことを2回聞かれたら、より具体的なヒントを出す
  3. 危険な操作をしようとしていたら、はっきり止める
- 呼んだ回数は記録される(評価には使わないが、比較画面で表示)
- ※ API接続不可の環境向けフォールバック:定型の「着眼点ヒント」を段階表示

## 9. 図面・用語解説

- **図面**:画面上部の常設ボタンでいつでも開ける。テスターで確認済みの箇所にマーカーが付いていく
- **用語解説**:会話・選択肢・図面内の専門用語(CP、導通、短絡、地絡、局番など)に下線マーカー。クリックでポップアップ解説
- 解説文は手順書付属の用語集をそのまま流用(「やさしい説明」列)

## 10. ランダム不良生成(Stage 1の例)

毎プレイ、以下から0〜3件をランダムに仕込む:

- 異線番間の短絡(R-S間など。※実体験ネタ)
- 同一線番の断線(導通が鳴らない)
- 電源線とE間の地絡
- 圧着端子の緩み(たまに導通したりしなかったりする"いやらしい"不良)
- 線番の入れ違い(図面と実配線の不一致)

不良なしの回もあり得る(「異常がないことを確認する」のも仕事、という学び)。

## 11. 合否判定と比較画面

- **合格条件**:ステージ目標達成+大ミス0回+仕込み不良をすべて発見・対処
- **不合格**:大ミス発生、または不良を見逃したまま完了申告
- クリア後の比較画面:
  - プレイヤーの操作ログ(時系列)と模範手順を左右に並べて表示
  - 「模範ではここで無電圧確認をしています」のような差分コメント
  - ベテランを呼んだ回数、かかった時間も参考表示

## 11.5 操作ログの保存(決定)

- 操作ログ・クリア履歴・ミス回数は**ブラウザ内(localStorage)に保存**する
- 本人が「前回の自分」と比較して成長を確認できるようにする(教育記録としての提出は行わない)
- 保存されるのは遊んだPC・ブラウザ内だけ。PCを変えると記録は引き継がれない(この割り切りでサーバー不要のシンプル構成を保つ)
- 記録を消したい場合のための「記録をリセット」ボタンを設定画面に用意する

## 12. 技術構成(案)

| 要素 | 技術 |

| ゲーム本体 | React(単一ファイルArtifactから開始可能)/ Canvas or CSSグリッドでドット絵マップ |

| データ | 手順書64ステップ+用語集をJSON化してゲームデータの土台にする |
| 記録保存 | localStorage(サーバー不要) |
